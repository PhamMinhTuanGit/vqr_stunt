# CasADi symbolic Pinocchio model audit — Step 4

## Scope

This audit covers only the CasADi symbolic version of the numerical Pinocchio
model developed in Steps 1–3. It creates symbolic rigid-body dynamics,
kinematics, rolling constraints, manifold integration, and selected analytic
derivatives. It does not add IPOPT, an NLP/`Opti` problem, trajectory
optimization, phase scheduling, costs, controller integration, or hardware
integration.

The symbolic model is produced by casting the already constructed
`PinocchioModel::model()` to `casadi::SX`. It therefore reuses the same URDF,
free-flyer model, name-resolved actuator mapping, canonical wheel mapping,
contact geometry, wheel radius, wheel axis, and ground normal. The URDF is not
parsed a second time.

## Dependency and build-support audit

- Pinocchio version: `4.1.0`.
- CasADi version: `3.7.2`.
- The existing Pinocchio build cache contains
  `BUILD_WITH_CASADI_SUPPORT:BOOL=OFF`. Consequently its exported CMake target
  does not discover or propagate CasADi for consumers.
- The installed Pinocchio nevertheless contains the templated
  `pinocchio/autodiff/casadi.hpp` scalar/context implementation. A minimal
  Pinocchio `casadi::SX` CRBA program compiled, linked, and evaluated
  successfully against the existing installations.
- The minimal integration fix is local to `controller/stand_wheel`: CMake finds
  the existing CasADi package under `third_party/casadi/install` and links
  `casadi::casadi` explicitly. Pinocchio itself was not rebuilt or modified.
- The complete Step 4 test compiles Pinocchio CRBA, RNEA/nonlinear effects,
  ABA, frame kinematics/Jacobians, CoM, and manifold integration with the
  CasADi scalar. No callback or finite-difference surrogate is used to create
  the symbolic dynamics.

## Configuration and velocity convention

The model dimensions remain `nq=27`, `nv=22`, and `nu=16`.

`q` uses Pinocchio's configuration manifold:

- free flyer: seven configuration entries (world translation followed by the
  normalized quaternion coefficients used by Pinocchio) and six tangent
  velocity entries;
- 12 bounded leg revolutes: one configuration and one velocity each;
- four continuous wheel joints: a normalized `(cos(theta), sin(theta))` pair
  per configuration and one angular velocity each.

Thus symbolic code never treats `q` and `v` as equally sized Euclidean
vectors. Joint and actuator indices come from the Step 1/2 name mappings.

## Symbolic functions

For `Nc` active contacts, supplied and stacked in caller-provided order, the
`casadi::SX` functions have these shapes:

| Function | Inputs | Output |
|---|---|---|
| `mass_matrix` | `q[27]` | `M[22 x 22]` |
| `nonlinear_effects` | `q[27], v[22]` | `h[22]` |
| `generalized_actuation` | `tau[16]` | `S^T tau[22]` |
| `contact_jacobian` | `q[27]` | `J_force[3*Nc x 22]` |
| `generalized_contact_force` | `q[27], lambda[3*Nc]` | `J_force^T lambda[22]` |
| `forward_dynamics` | `q[27], v[22], tau[16], lambda[3*Nc]` | `vdot[22]` |
| `center_of_mass` | `q[27]` | world CoM `[3]` |
| `wheel_centers` | `q[27]` | world `[FL; FR; HL; HR] [12]` |
| `contact_positions` | `q[27]` | world `[FL; FR; HL; HR] [12]` |
| `contact_jacobians_all` | `q[27]` | world `[J_FL; J_FR; J_HL; J_HR] [12 x 22]` |
| `support_line` | `q[27]` | FL point, HR point, horizontal line direction, perpendicular CoM vector, squared distance `[13]` |
| `rolling_matrix` | `q[27]` | `A_roll[3*Nc x 22]` |
| `rolling_residual` | `q[27], v[22]` | `A_roll(q) v [3*Nc]` |
| `integrate` | `q[27], dv[22]` | `q_next[27]` |

The parity test uses the deliberately noncanonical active order `HR, FL, HL`
(`Nc=3`) to verify that `lambda` and all active rows follow caller order. Force
Jacobians and `lambda` use world XYZ blocks. Rolling blocks retain the Step 3
contact-frame row order `[normal, lateral, rolling]`.

## Symbolic dynamics formulation

The expressions implement

```text
M(q) vdot + h(q,v) = S^T tau + J_force(q)^T lambda
```

`M` is generated by symbolic CRBA and `h` by symbolic Pinocchio nonlinear
effects. `S` is copied from the Step 2 name-resolved selection matrix. Contact
points/Jacobians are generated from the Step 1 wheel frame IDs and geometry.

`vdot` is generated using Pinocchio's symbolic ABA with generalized force
`S^T tau + J_force^T lambda`. This is algebraically the requested solve and
does not form an explicit matrix inverse. Numerical Step 2 uses an LDLT solve,
so their agreement also cross-checks two independent forward-dynamics
algorithms.

## Symbolic kinematics and rolling constraints

All positions and directions are world-expressed. Each wheel center and axle
come from its name-resolved Pinocchio BODY frame. The physical centerline tread
point is recomputed with the Step 1 projected-normal construction.

The rolling/lateral directions are recomputed symbolically from current wheel
orientation, not fixed world X/Y axes:

```text
e_roll = normalize(e_axle cross e_normal)
e_lat  = normalize(e_normal cross e_roll)
```

As in Step 3, `J_carrier` is the material-point force Jacobian with the named
wheel spin column removed. The implemented block is

```text
A_i[0,:] = e_normal^T J_carrier
A_i[1,:] = e_lat^T    J_carrier
A_i[2,:] = e_roll^T   J_carrier - radius * e_wheel^T
```

so `A_i v = [v_normal, v_lateral, v_rolling-r*qdot_wheel]`. This API remains
separate from `J_force^T lambda`.

The support-line output uses the current FL and HR contacts, projects their
direction and the CoM offset onto the configured ground plane, and returns the
CoM component perpendicular to that line plus its squared norm.

## Manifold integration

`integrate(q,dv)` calls `pinocchio::integrate()` on the CasADi-cast model. It
does not use `q + dv`. Consequently free-flyer quaternion composition and each
continuous wheel's two-coordinate representation follow exactly the same
manifold convention as the numerical model.

Across five deterministic random valid states near the nominal stance:

- symbolic-versus-numerical integrate maximum error: `1.387779e-17`;
- free-flyer quaternion norm error: `1.110223e-16`;
- maximum continuous-wheel pair norm error: `1.110223e-16`.

## Derivative validation

Configuration derivatives are manifold-aware tangent derivatives. The
functions first form `integrate(q,dq)` symbolically and differentiate with
respect to `dq`, then callers evaluate at `dq=0`. Their dimensions are:

- `d(vdot)/dq_tangent`: `22 x 22`;
- `d(vdot)/dv`: `22 x 22`;
- `d(vdot)/dtau`: `22 x 16`;
- `d(vdot)/dlambda`: `22 x (3*Nc)`;
- `d(A_roll v)/dq_tangent`: `(3*Nc) x 22`;
- `d(A_roll v)/dv`: `(3*Nc) x 22`;
- `d(CoM)/dq_tangent`: `3 x 22`.

Every derivative entry was finite with no NaN or infinity. Directional central
differences used `epsilon=1e-5`; maximum absolute errors were:

| Derivative | Error | Tolerance |
|---|---:|---:|
| `vdot` wrt tangent `q` | `2.237962e-08` | `1e-5` |
| `vdot` wrt `v` | `1.334923e-08` | `1e-6` |
| `vdot` wrt `tau` | `1.552990e-08` | `1e-7` |
| `vdot` wrt `lambda` | `2.184276e-08` | `1e-7` |
| rolling residual wrt tangent `q` | `6.913831e-12` | `1e-7` |
| rolling residual wrt `v` | `5.390949e-12` | `1e-9` |
| CoM wrt tangent `q` | `2.704822e-12` | `1e-9` |

## Build and test

From the repository root:

```bash
cmake -S controller/stand_wheel \
  -B /tmp/vqr_stand_wheel_step4 \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="$PWD/third_party/install"
cmake --build /tmp/vqr_stand_wheel_step4 -j1
ctest --test-dir /tmp/vqr_stand_wheel_step4 --output-on-failure
```

The final result was four tests passed out of four: the Step 1 model smoke
test, Step 2 full dynamics test, Step 3 wheel-contact test, and Step 4 CasADi
model test. `-j1` is recommended because compiling the Pinocchio/CasADi
template instantiation is memory intensive. The symbolic target uses `-O1` in
Release for the same reason.

To print all Step 4 parity and derivative values directly:

```bash
/tmp/vqr_stand_wheel_step4/casadi_model_test \
  vqr_description/vqr_urdf/urdf/VQRWheel.urdf
```

## Assumptions and unresolved issues

- Pinocchio's original build option for CasADi remains OFF. The installed
  template implementation is proven functional and linked explicitly by this
  module, but a future system-wide Pinocchio package upgrade should either
  enable `BUILD_WITH_CASADI_SUPPORT` or preserve this explicit CasADi link.
- The CasADi installation is repository-local by default. It can be replaced
  by setting `STAND_WHEEL_CASADI_ROOT` to another compatible CasADi 3.7+
  package.
- Contact geometry retains the rigid, centerline cylindrical tread and planar
  ground assumptions from Steps 1–3. Tire compliance, a finite patch, terrain
  curvature, friction limits, and contact-force feasibility are not modeled.
- The symbolic physical contact location is reselected from the lowest tread
  geometry at each configuration. `J_force` remains the instantaneous
  material-point Jacobian used by dynamics, matching the established Step 1/2
  convention.
- Normalization denominators require the wheel axle not to become parallel to
  the configured ground normal and the FL–HR support points not to collapse to
  one horizontal point. The numerical Step 3 API rejects the former
  degeneracy; symbolic callers must keep optimization iterates away from both.
- Functions are built for a fixed active-contact subset and ordering. A caller
  that changes the subset must build/cache the corresponding function set.
